# Evidence Desk — rules for the agent working this repository

- **What this is.** evidence-desk, a project that builds itself through Open Autonomy. `CONSTITUTION.md` is what it is and must remain. `ROADMAP.md` holds notable intentions and outstanding outcomes; `CHANGELOG.md` holds notable changes landed on main. Strategy develops roadmap scope under the owner mandate in project-communications. Hermes PM owns discovery, explicit authorized request intake, delivery reconciliation and changelog distillation, and queues fleet work. Constitution checks apply at conception and merge; an empty queue grants no scope authority. Contributors use ordinary code, PRs and conversations; no shared-document edit or handoff is required. `CONTRIBUTING.md` is how code is written here. `hermes/` is you.
- **Verification.** Automated tests are banned; no tests or persistent test harnesses may be committed to main. The rationale is in `CONSTITUTION.md`: test cruft compounds until progress becomes impossible. Each develop agent verifies its feature through REPL-style manual use and records actual observations in its handoff. Never run test suites or commands/hooks that invoke them.
- **Verify.** This is a local folder application; verification uses disposable synthetic workspace folders, never customer evidence. Run application commands, dependency installation and `bun run check` through the machine's World: `volter-world attach <world> -- <command>`. Configure its host-side environment beside the checkout using the machine's World instructions before running these commands. PM must document the actual application run command in README as it lands; the initial source only typechecks a placeholder. Add vendor twins when application dependencies emerge, seed their state through vendor APIs, and put behavioral responses in world handler files. The fleet's real GitHub and model connections are development infrastructure, not customer integrations. Never substitute real customer credentials for a twin. You cannot reach production and must not try.
- **Git.** You cannot push to `main` and must not try. Work on `agent/<task id>` off a fresh `origin/main`, commit small with the task id first in the subject, and push the branch; the landing workflow opens the pull request and it merges itself when the checks pass. Never rewrite history, never force-push.
- **The community.** `.open-autonomy/community.ts` is your door to the repository's issues and discussions (`GITHUB_API_URL` and `GITHUB_TOKEN`: in the stack, the valve's GitHub port and the word `valve` — the project's own GitHub App answers); Discord is the project's own application and bot, used through Hermes's native tools. The `community` skill says what to answer, what to preserve for scrum and what to decline; its job runs every quarter hour.
- **Secrets.** There are none for you to use: your model calls and your pushes are authorized outside your reach. Never read or print `.env` files or key material; your sessions are published live.
- **Do not edit** `LICENSE`, `.github/workflows/`, `container/`, `.open-autonomy/reporter.ts`, or anything under `hermes/` except a skill a task asks you to improve.
- **Cost.** Your calls are metered and public. Read before writing; manually verify the feature; stop when verified.
